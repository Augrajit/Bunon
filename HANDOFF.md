# HANDOFF: how to continue Bunon without the original assistant

Written 26 Nov 2026 on branch `v2`. Read this together with `CLAUDE.md` (rules and commands), `PLAN_V2.md` (the approved plan; its decisions block wins) and `SPEC.md` (dated decision log, D1–D14 and later).

**State in one paragraph.** `main` (the live app, https://buunon.streamlit.app/) still runs the pre-PLAN_V2 demo. `v2` holds D12 (success = good pieces after QC within a tolerance), D13 (order store, service layer, the app around one order's timeline) and D14 (the thin loop end to end: sourcing → offers → split → update → forecast → rescue → QC → track record). All of it replays offline from the LLM cache. Merge `v2` into `main` only when the product owner approves.

## 1. The rules (never break these)

1. **The LLM never produces a number.** Enforced in code:
   - *Reading text* (`agent.parse_order`, `parse_reply`, `parse_update`, `parse_news`, `steer`): every value comes with `source_span`, a verbatim quote. `textnum.contains(text, span)` must find the quote, and `textnum.states_number(span, value)` / `states_date(span, value)` must confirm the quote states that value. Otherwise the value becomes `None` with status `rejected` or `missing`, and a human enters it.
   - *Writing text* (`agent.write_memo`, `analyst.answer`): the LLM may write no digits and no number words. It may use only `{{key}}` placeholders from a `FactSheet` (numbers computed by the engine) and `{{fac:F0123}}` for factories. `agent.check_text` rejects violations; then one retry; then a deterministic template.
   - *Decisions* the LLM suggests (accept/reject/counter, status) are settled by code (`validate_reply`: a "yes" with a lower verified quantity or a delay becomes "counter"; zero pieces becomes "reject").
   - News severity is a label only; its effect is the fixed `SEVERITY_TABLE` in `config.py`.
2. **Approvals.** Nothing is ever sent to a factory automatically. Every plan, split, rescue and outgoing message needs a click by an exporter role (`service._require_exporter`). "Sent" means "shown in the factory's in-app inbox". Only the Quality inspector records QC. Roles are recorded, never names.
3. **Offline demo.** `BUNON_LLM_MODE=offline` (default) reads only `data/llm_cache/`; a miss raises `CacheMiss` and the caller falls back to a template or hand entry, never an error. The cache key covers the provider, model, task, prompt version and the **exact prompt text**. So changing any of these invalidates cached answers: a prompt string, a `*_VERSION`, a demo input, persona text, or **anything that changes engine numbers** (they appear in memo and analyst prompts). After such a change:
   ```
   set BUNON_LLM_MODE=live   (needs GEMINI_API_KEY in .env; never print or commit it)
   .venv/Scripts/python.exe -m bunon.warm_cache
   ```
   Then walk the whole app once in live mode (the loop's offer/update/rescue parses are also warmed by `warm_cache`). Then switch back to offline and run `pytest -m sweep`: it fails if the intake answer is not cached. Live calls are capped: 40 per visitor session and 400 per day.
4. **Pseudonymisation (public repo).** Factories appear only as `F0001`–`F3196`, with coordinates rounded to 2 decimals and workers rounded to 50. Never commit or send to the LLM factory names, `os_id`, addresses, `data/raw/` (raw CSV) or `data/private/` (the ID mapping); both directories are gitignored. `agent.assert_pseudonymous` checks every prompt; `tests/test_data_gen.py` scans every DB cell.
5. **Synthetic is labelled.** All capacity, price and history data is synthetic (seed 42) and labelled "synthetic" in the UI. Personas are **hand-written by the team**, labelled simulated, and never generated by the LLM. Values marked `ASSUMPTION` / `PLACEHOLDER` in `config.py` wait for research (`RESEARCH_ASKS.md`); never tune them to improve results.
6. **Working method.** Work on `v2`. Commit after every working step with tests green and push to `v2`. Record each design change in `SPEC.md` with its reason and before/after numbers. Update `PROMPTS.md` when a prompt changes. Run `pytest -q` and `pytest -m sweep` before committing a UI change. At each milestone, an independent reviewer (a person, or a fresh AI session) checks it against SPEC.md, rule 1, rule 2 and rule 3 before work continues.

## 2. Running it locally (Windows, Python 3.11)

```
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m streamlit run app.py            # http://localhost:8501
.venv/Scripts/python.exe -m pytest -q                        # ~170 unit tests, ~1 min; 5 skips on a clean clone are normal
.venv/Scripts/python.exe -m pytest tests/test_loop.py -q     # one file
.venv/Scripts/python.exe -m pytest -m sweep -q               # app click-through at 24 extreme settings, ~5 min, offline
.venv/Scripts/python.exe -m bunon.personas                   # validate data/demo/personas.json
```

The login page has a "Continue as demo exporter" button; nothing typed there is checked or stored. In the sidebar, pick a role. To walk the loop: confirm the order → approve the plan → approve and send the sourcing round → "Go to day 2" → approve the split → "Go to day 12" → choose a rescue → approve, send → "Go to day 26" → switch the role to Quality inspector → Record QC → the track record appears.

### UI
`app.py` renders only. Login gate → welcome → role switcher → three views: **Order timeline** (`view_timeline`: intake, plan + memo + approval, then `section_sourcing`, `section_offers`, `section_split`, `section_update`, `section_rescue`, `section_qc`, `section_record`, then "Ask Bunon" and the event timeline), **Show the maths** (`view_maths`), **Factory app** (`view_factory`, phone frame). ## 6. Where to look when something breaks

- **Sweep says "timeline missing" or pydantic `model_type` errors:** a module is missing from `app.py`'s reload list.
- **Sweep fails at intake / memo shows the template:** cache miss; something in the prompt changed (rule 3).
- **Different numbers between runs:** look for unordered sets/dicts feeding the optimizer or a prompt; sort by `(-qty, id)` as the re-plan diff does.
- **A visitor sees another's data:** stores are per visitor session; check `store.session_db_path` and `BUNON_STORE_DIR`.
